## M3–M6 Configure, runs, nodes, verify, demo, security, rollback

- **Configure** (`static/configure.js`): the config form by group plus template inputs, live validation
  (`POST /api/values`), the rendered values file with a line diff against the live release, the Phase 3 request
  previews, the test pod, Discover and Preflight. Delete arms on the first click instead of a `confirm()`.
- **Discover/Preflight** (`checks/preflight.py`): read-only `az`, `kubectl` (`get`, `auth can-i`, `version`), `helm`
  (`get`, `list`, `history`, `status`), enforced in `k8s.py` (`ReadOnlyError`). A Forbidden read names the pipeline
  scenario to run instead. Issuer drift, foreign providers (protected marked), orphaned writers (`checks/writers.py`)
  and the live vs committed release are checked.
- **Runs** (`runner.py`, `ado.py`, `static/runs.js`, `ui.runControl`): prepare → approve (bound to `request_sha256`)
  → `az pipelines run` → poll → REST logs with a bearer that is never stored → parse. State-changing runs need
  approval, destructive ones the cluster name typed in. DryRun defaults to true. Guards: demo mode, PRD gate, values
  errors, ChartRepo, protected provider, secret-shaped parameter names.
- **Nodes, Verify, Troubleshoot, Artifactory** (`static/nodes.js`, `verify.js`, `troubleshoot.js`, `artifactory.js`):
  three layers per node, kubelet start vs config mtime, fresh nodes, node migration with run controls; the pull
  verdict with the proof pod and audit attribution (`checks/verify.py`); the evidence bundle diagnosis; realm probe,
  AQL, storage, binary integrity, token scope, remotes and orphaned mappings (`checks/artifactory.py`).
- **Demo, Security, Rollback, report** (`static/demo.js`, `security.js`, `rollback.js`, `report.py`): rehearsal ticks,
  the demo gate and demo mode; the 8-row review with a recorded status and note, the PRD banner, chart RBAC, the
  stored-log leak scan, open items; the five rollback items as runs; the Markdown/JSON report.
- **Replay** (`--fixtures kcp_console/tests/fixtures/sandbox`): a separate store seeded from `*.seed.json`; fixtures are
  generated by `python3 -m kcp_console.tests.fixtures.make_fixtures` and `test_runtime.FixturesTest` fails if stale.
- Tests: `tests/test_redact.py` (6, every write path) and `tests/test_runtime.py` (29): read-only enforcement, ADO parameters, guards, checks, replay server end to
  end, the ADO bearer and the replay token never on disk or in the log.

## M2 Server, Overview, Simulate

**Built**

- `kcp_console/server.py`: the serverless console's security model (127.0.0.1, session token in `#t=` sent as
  `X-Console-Token` and compared with `hmac.compare_digest`, Host and Origin/`Sec-Fetch-Site` allow-lists, strict
  CSP, nosniff, no-referrer, DENY framing, `no-store`, JSON bodies ≤ 1 MiB, static allow-list). API so far:
  `session`, `knowledge`, `defaults`, `validate`, `configs`, `sim/scenarios`, `sim`, `sim/<id>`, `sim/<id>/events`.
- `kcp_console/__main__.py`: `--port 8766`, `--no-browser`, `--new-token`, `--print-url`, `--fixtures`; refuses
  non-loopback binds without `--i-know-this-exposes-credentials`.
- `kcp_console/store.py`: `.kcp-console/` (or `$KCP_CONSOLE_HOME`); configs 0600 in a 0700 dir; refuses any
  config the redactor would change.
- `kcp_console/redact.py`: JWTs, JFrog reference tokens, Authorization/Bearer, `curl -u`, `X-JFrog-Art-Api`,
  `JFROG_ACCESS_TOKEN` / `JFROG_DOWNLOAD_TOKEN` / `JfrogDownloadToken` / `ARTIFACTORY_ADMIN_TOKEN` /
  `artifactory-download-token` / ADO PATs, `--set ...accessToken=`, `#t=`, and the live env values.
- UI (`static/`): Overview (status at a glance, story, where things stand, four SVG diagrams, open items,
  testing performed / not performed, environment) and Simulate (scenario list, verdict, root cause, causal
  chain, swim-lane timeline, ranked findings with evidence and dry-run-first next action, three-layer table per
  node, raw evidence).

**Decisions**

- The KCP redactor does not mask a `value` key wholesale (the serverless one does): kubelet env items are
  `{name, value}` pairs whose values are what the console must show. It masks the value of an item whose name
  is secret-shaped instead.
- The `NAME: value` form is masked only for named secret variables, so runbook prose ("rotate
  $ARTIFACTORY_ADMIN_TOKEN: it was typed...") and containerd's "anonymous token: unexpected status" survive.
  Both are pinned in `test_server.RedactTest.test_runbook_facts_survive`.
- Simulations are deterministic and take milliseconds, so `POST /api/sim` runs inline and returns the result;
  the last 20 are kept for `GET /api/sim/<id>` and the SSE replay.
- Only built tabs are shown; the rest appear with their milestones.

**Verification:** 98 unit tests pass; `check-all` 23/23. The console ran on 127.0.0.1:8766 in Chromium
(Playwright): Overview and Simulate render with no console errors, and the CSP blocked Playwright's own
`eval`-based waits, which confirms the policy is enforced.

## M1 Simulator

**Built**

- `kcp_console/model.py`: the config schema with the sandbox defaults, values-file rendering (byte-identical to the
  committed pilot file, pinned by a test), provider/mapping request bodies, the test-pod YAML and the validators
  (§7, §8, §10 rules, the protected provider, a different-issuer refusal).
- `kcp_console/sim/world.py`: nodes, kubelet (reads its config at its own start), the plugin (token URL, DNS
  failure on a doubled scheme, exchange), containerd, the DaemonSet setup step with MergeFiles' observed
  behaviour, orphaned writers that revert a second after each write, both caches, and Artifactory (providers,
  mappings, permissions, promote, AQL, realm probe, dormant remote, audit). Output is rendered in the pipeline's
  own formats (pod events, QUICK SUMMARY, plugin JSON lines, helm values, manifest) so the console's parsers read it.
- `kcp_console/diagnose.py`: the rule engine. 9 troubleshooting rows plus the rules the bug table and guards
  add (wrong node checked, Forbidden as a user principal, cached image, cached token, dormant remote, virtual
  promote, arch suffix, 0-byte binary, helm --wait, old reset safety check, read-only diagnostic artifact,
  truncated output, control pod). Each finding carries the matched evidence lines, a "not observed" label for
  the two expected-but-unseen rows, and a next action that is dry-run first.
- `kcp_console/checks/three_layers.py`: values file vs live values vs manifest vs node entry vs the plugin's
  newest URL, per node, with the fix for the layer that disagrees.
- `kcp_console/sim/engine.py`, `sim/__main__.py` (`list | run <name> | check-all`) and 23 scenario JSONs, each
  with expected verdict, root cause, findings and causal-chain fragments.

**Decisions**

- `defaultCacheDuration` longer than the mapping's `expires_in` is a warning, not an error: the pilot ran 5h
  against 3600s and pulled fine. Whether kubelet can hand containerd an expired token inside the window is
  unverified; it stays with the open "keep 5h?" item.
- A release installed with values other than the committed file (`install` with `values=`) leaves the committed
  file untouched, so the three-layer diff shows the live layer disagreeing, as it would on a real cluster.

**Verification:** 80 unit tests pass; `check-all` 23/23.

## M0 Spec and parsers

**Built**

- `docs/kcp-console-spec.md`, in the same structure as `docs/console-spec.md`.
- `kcp_console/knowledge.py` holds the runbook as data: every table and caveat. The UI and the report render it.
  `tests/test_knowledge.py` pins the counts the checklist names (11 scenarios, 19 bugs, 9 troubleshooting rows,
  8 security rows, 8 open items, 5 + 6 testing rows...).
- `kcp_console/logic.py` holds the decision logic shared by the checks and the simulator:
  - the plugin's token-URL formula, and a scheme count that also catches Go's `https://https//` form;
  - kubelet `matchImages` matching (per-label globs, port, path prefix);
  - `MergeFiles` with the observed "kept-stale" behaviour and the source-reading "appended" behaviour;
  - `RESET_NODE_JFROG_ENTRY` in both versions: the old one counted `env:` items and aborted; the fixed one
    checks indentation and skips correct nodes;
  - durations, the kubelet-start vs config-mtime comparison, the realm parse, the dormant-redirect check, the
    download-URL arch-suffix check, the binary-size guard, approval request hashes, and case-insensitive node
    names.
- `kcp_console/parse/`:
  - `yamlish`: a stdlib YAML subset reader;
  - `kubelet_config`: parse, render and the chart-supplied `tokenAttributes` check;
  - `plugin_log`: JSON or plain lines, the 5-row meaning table, newest-by-timestamp;
  - `events`: pod events → PASS/FAIL/INCONCLUSIVE, the kubelet journal, and `Forbidden` lines with a
    user-principal flag;
  - `helm`: values, the rendered manifest, RBAC objects;
  - `summary`: the QUICK SUMMARY footer first, the full log as fallback, and CHECK_JFROG_POD_CONFIG sections.
- `kcp_console/tests/runbook_strings.py` holds fixtures built from the runbook's exact strings: containerd's
  anonymous 401, the plugin's doubled URL and DNS error, the pull events (142,944,877 bytes in 10.487 s), the
  `already present` line, kubelet's exec failure, the `Forbidden` from `operator@example.com`, and node files
  with the `env:` items.

**Assumption to fix with the first live run.** The QUICK SUMMARY layout and the plugin's JSON field names are
reconstructed from the runbook's field names. The parsers are tolerant, but replace the fixtures with a recorded
run.
